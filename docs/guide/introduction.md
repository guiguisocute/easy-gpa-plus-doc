# 认识 EasyGPA Plus

EasyGPA Plus 为不同班级提供可配置的综合测评、材料审核和成绩核对。它把材料、认定、申诉与结算串成一条可追溯的流程，让每一分都能说清来处。

- **学生**：提交佐证、追踪进度、查看实时成绩、提出申诉。
- **综测小组**：独立审核、复评与异议处理。
- **班级管理员（班管）**：评分方案、名单、分发、仲裁与报表。
- **平台运维**：班级隔离、对象存储、通知与备份；AI 辅助按需配置。
- **你的 Agent**：通过 [MCP](/guide/agent) 读取资料、上传佐证、审核与统计，权限由账号掌握。

## 角色与视角

系统中的真实账号角色决定权限。班管可以切换到较低角色的视角检查页面，但切换视角不会改变真实身份，也不会获得新的数据权限；审计中始终记录真实操作者。

| 角色 | 主要页面 |
| --- | --- |
| 学生 | 提交材料、综测总览、我的提交、我的申诉、我的成绩表、评定细则、举报台 |
| 综测小组 | 待办任务、初审工作台、处理申诉、扣分与异议、举报复核、我的审核量、历史审核；被任命为副班管时另有「副班管仲裁」 |
| 班级管理员 | 班级看板、审核明细、班级成员、班级资料、方案编辑器、时间窗口、功能开关、分发、加分台、仲裁与申诉、处理历史、专业素质分、导出中心、审计日志 |
| 平台运维 | 班级与班管、模板库、Agent 配置、邮件与通知、队列与任务、备份与恢复、开关与阈值、组件健康、部署与版本、平台审计 |

三类业务角色都能在左下角账号菜单进入「账号设置」。运维身份只管理平台，不能读取班级材料、会话或学生业务数据。

## 两种班级模式

班级首次配置时，由班管选择一种模式：

- **普通模式（推荐）**：班管统筹，系统把材料随机派给两名综测小组成员独立审核，分歧交班管仲裁；班管本人的事项交副班管处理。
- **共治模式（测试版）**：成员主动加入，共同事项投票决定，个人案件由随机评审处理。详见[班级共治](/guide/governance)。

::: warning 共治模式为测试版
共治模式尚未经过真实班级的生产验证，规则与界面可能调整。首次使用和正式计分请选择普通模式。
:::

![首次配置时的模式选择：普通模式标注推荐，共治模式标注测试版](/images/mode-choice.png)

已开始正式计分的周期不能中途切换模式。

## 核心约定

- **实时成绩表**根据已认定材料、基础分、扣分和专业成绩形成当前成绩，同时显示未结事项，不等待整表终审。
- **成绩确认**是学生对当前版本的自愿核对记录：不阻塞结算，不取消申诉权，也不存在自动确认。
- **单项审核**由两名审核人独立审查一条材料，冲突按仲裁流程处理。
- **结算**要求提交结束、单项定分、未结事项清零且专业成绩完整，之后生成正式成绩记录。
- **本人事项回避**：管理者不得终裁以自己为评分或举报对象的事项。

术语的完整定义见[术语表](/reference/glossary)。

## 数据边界

每个班级的数据由租户隔离保护，普通用户只能访问当前班级中本人角色允许的资源。AI 与 Agent 不会绕过页面权限：它们最多形成草稿或预填，提交、审核、仲裁、结算和导出仍需有权限的用户在对应页面确认。结算和评分由后端规则执行，模型不参与出分。

仓库不内置任何学生名单或学校素材，示例一律使用虚构数据。
