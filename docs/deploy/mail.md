# 邮件通知

邮件是可选能力，用于验证码、找回密码和业务通知。在运维台「邮件与通知」选择发信通道，保存配置后运行时生效，无需重启。部署者需要自行准备已验证的发信地址和凭据，仓库不附带可用账号。

| 通道 | 凭据与连接 | 邮件正文 | 自动投递反馈 |
| --- | --- | --- | --- |
| 腾讯云 SES（默认） | SecretId、SecretKey、地域 | 腾讯云已审核的模板及模板 ID | 支持腾讯云反馈同步 |
| SMTP | 主机、端口、TLS 方式；需要认证时填写用户名与密码 | 仓库本地模板 | 暂不支持 |
| 阿里云邮件推送 | AccessKey ID、AccessKey Secret、地域 | 仓库本地模板 | 暂不支持 |
| Resend | API Key、已验证发件域 | 仓库本地模板 | 暂不支持 |

## 从配置到启用

1. 在部署环境设置 `MAIL_SECRET_KEY`：32 字节密钥，可用 `openssl rand -hex 32` 生成。它加密运维页保存的邮件凭据，设置或更换部署环境后重启相关服务。
2. 在「邮件与通知」选择通道，填写连接参数、凭据和认证发信地址；按需填写发件人名称与回复地址。
3. 需要业务通知时，另设通知发信地址与显示名。通知地址必须使用与认证邮件不同的域名，例如认证使用 `auth.example.org`，通知使用 `notify.example.org`；两者均须在所选服务中获得发信授权。
4. 保存后向自己的邮箱发送自检邮件，核对正文、链接和发件人。腾讯云还需确认本页保存的模板 ID 对应已审核模板。
5. 确认通知地址和模板准备完成，再启用业务邮件。业务邮件默认暂停，验证码、找回密码和通道自检独立运行。

业务邮件暂停会跳过新事件并清理待发积压，恢复后只发送新的进展，不补发暂停期间的通知。

### 腾讯云 SES

地域只支持 `ap-guangzhou` 与 `ap-hongkong`，默认 `ap-guangzhou`。填写腾讯云凭据、已验证发信地址和下文的模板 ID。

`.env` 中的 `TENCENTCLOUD_*` 变量是独立的部署回退配置，适用于没有运维库的精简部署或清空网页通道后的回退。一旦使用网页配置，就需要保存完整、独立的通道设置，不会从环境变量拼接缺失的凭据。

### SMTP

| 设置 | 要求 |
| --- | --- |
| 主机 | 域名或 IP，例如 `smtp.example.org`；不带协议、端口或路径 |
| 端口 | 1—65535 的整数，默认 587；以邮件服务商给出的端口为准 |
| 连接安全 | `starttls`（默认）或 `tls`（隐式 TLS） |
| 用户名与密码 | 同时配置；仅在服务商允许无认证的 TLS 中继时，两项都可留空 |

SMTP 始终校验证书，最低使用 TLS 1.2。选择 STARTTLS 后，服务端不支持升级加密会直接失败，不会降级成明文。用户名与密码分别加密保存，不提供跳过证书校验的选项。

已有凭据时，更换 SMTP 主机或端口必须同时重新填写用户名和密码，或明确同时清除两项。系统不会把原服务的凭据自动发送给新地址。

### 阿里云邮件推送

填写 AccessKey ID、AccessKey Secret 和已配置发信地址的地域。支持 `cn-hangzhou`（默认）、`ap-southeast-1`、`us-east-1`、`eu-central-1`；服务端按地域选择固定 HTTPS 接口，无需填写 API 地址。

认证与通知的发件人显示名各不超过 15 个字符。

### Resend

先在 Resend 控制台验证发件域，并创建具有相应发信权限的 API Key。在运维台选择 Resend，填写 API Key 和该域下的认证发信地址；需要业务通知时，同样配置独立通知域下的发信地址。

API Key 使用 `MAIL_SECRET_KEY` 加密保存，配置查询只返回是否已保存，不回显原值。服务端使用固定 HTTPS 发送接口，无需填写地域或 API 地址。

SMTP、阿里云与 Resend 均使用仓库本地模板，不需要云模板 ID，也不会读取腾讯云环境变量中的凭据。

## 模板

| 模板 | 用途 |
| --- | --- |
| `verification_code` | 邮箱验证码 |
| `password_reset` | 找回密码 |
| `mail_test` | 运维自检 |
| `notification_alert` | 合并短时间内的重要通知 |
| `notification_digest` | 每日汇总 |

模板 HTML 位于主仓库 `asset/mailtemplate/`，`MAIL_TEMPLATE_DIR` 可指定本地模板目录。前三个用于认证与自检，后两个用于业务通知。腾讯云需要申请对应云模板并填写 ID；业务邮件暂停时，两个通知模板 ID 可以暂不填写。SMTP、阿里云与 Resend 直接发送本地模板渲染的 HTML 和文本正文。

两份通知模板使用 `name`、`class_name`、`heading`、`summary`、`details`、`view`、`opt_out_token`、`sent_at`、`preference_note` 这些变量。请保留占位符和退订链接；正文不发送具体分数、学生材料或匿名审核身份。

仓库 HTML 中的 `https://gpa.example.org` 是占位地址，本地渲染时由 `PUBLIC_URL` 替换。上传到腾讯云 SES 控制台的副本必须先替换成自己的 HTTPS 站点地址，并使用固定域名链接，不要让变量提供整个 URL。应用内源模板保留占位地址，供运行时替换与校验。

目录中其他 HTML 与旧模板键只为兼容历史记录保留，对应旧发送路径已停用，新部署无需申请。

## 凭据保留与清除

所有通道共用 `MAIL_SECRET_KEY` 加密密钥，但各通道的账号凭据独立保存，不会在切换通道时混用。读取配置只返回凭据是否已保存，不回显原值。

- 不填写新凭据，保存时保留原值；需要更换时输入新值。
- 删除凭据使用明确的清除操作；接口省略字段表示保留，显式空字符串表示清除。
- 「清空并回退」清除所有通道的网页连接配置、凭据和腾讯云模板 ID，暂停业务邮件，并回到腾讯云部署配置。回退能否发信取决于环境变量是否完整有效。

`MAIL_SECRET_KEY` 已经加密过凭据后不要随意更换；更换会导致旧凭据无法解密，需要在运维页重新填写。此密钥是否就绪可在「部署与版本」核对，通道能否正常发信仍需自检。

## 投递状态

「已受理」表示供应商或 SMTP 服务器接受了发送请求，不代表邮件已进入收件箱。只有腾讯云通道目前会自动同步送达、退信、投诉等反馈；SMTP、阿里云与 Resend 暂不具备自动反馈同步，必要时到服务商日志核对。

如果请求已发出却没有拿到明确结果，日志会保留「结果待确认」，避免直接重发造成重复邮件。核对供应商记录后，再在日志中确认已受理或确认未受理；只有确认未受理的请求才应继续重试。死信重投入口在「队列与任务」。

## 用户侧设置

用户在「账号设置」中按分类选择通知、设置每日汇总、静默与限额，也可以通过邮件中的退订链接退订，这些设置对所有通道都生效。

当前流程是单项独立审核、分歧裁定、实时成绩与问题处理：学生核对当前版本不阻塞结算，也不取消申诉权。因此没有整表终审、定时确认或确认催办邮件。
